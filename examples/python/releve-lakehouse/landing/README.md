# landing/ — synthetic input only

A committed, **PII-free synthetic** statement (`synthetic-releve-2025-11.pdf`) lets the pipeline run
hermetically without any real bank data. It is generated by `generate_synthetic.py`, which lays out fake
transactions at the exact column geometry the `extract` handler keys on (date-comptable · libellé ·
date-valeur · debit/credit columns) plus a `TOTAL DES OPERATIONS` line, with fake PII shapes (a synthetic
card PAN, a `/BEN` beneficiary, a fake creditor ICS) so the anonymize gate has real work.

```bash
uv run --group build python landing/generate_synthetic.py   # → synthetic-releve-2025-11.pdf (5 fake txns)
```

The fixture is verified to pass **both gates** (extract == verify == printed totals; anonymize → 0 residual).

The pipeline is triggered by dropping a statement PDF into the `landing/` prefix of the `releves` Bucket
(an external SigV4 PUT with the ADR-0085 keypair, or the funcd S3 CLI), which trips `releve-landed` →
`releve-ingest` → a `releve-pipeline` run:

```bash
aws --endpoint-url "$AWS_ENDPOINT_URL_S3" s3 cp ./synthetic-releve-2025-11.pdf s3://releves/landing/
```

**Never put real bank statements here.** Real PDFs contain confidential data; they're dropped straight into
`landing/` at runtime (or kept in the gitignored `raw_data/`) and never enter the repo (see `.gitignore`).
Only a **synthetic**, PII-free statement named `synthetic-*.pdf` may be committed.
